# vz 1.0 Scope

Date: 2026-09-02
Status: committed scope. This doc is the contract for what 1.0 is and is not. Beads carry the work; this carries the decisions.

## The narrative

**vz 1.0 is the portable agent sandbox: one CLI and one runtime contract on macOS and Linux, an agent-native CLI surface, and full Docker compatibility via an in-sandbox engine — with the host staying clean on every platform.**

## Definition of done

One CLI, two host platforms (macOS + Linux), one runtime contract, agent surface = CLI + skill + `--json`, full Docker compat via the facade (dockerd-in-VM on macOS, rootless dockerd-in-sandbox on Linux), and zero "no" cells left in the Tier-1/Tier-2 rows of the runtime conformance matrix — on **both** platforms.

## Locked scope calls

1. **macOS guests are cut from 1.0 scope.** macOS guests require a real install: a pinned IPSW, sudo for provisioning, signed patch bundles for updates, and Apple's hardware-encrypted save-state that does not port. It is an install-shaped problem, not a runtime-shaped one. The code stays in the tree and `vz vm ...` flows keep functioning for existing users (macOS-only beta surface: security/correctness fixes and kernel-bump ride-alongs only; no new features, no 1.0 gates, not part of the portable contract). Revisit after Linux 1.0.
2. **The Linux facade is rootless dockerd-in-sandbox.** The facade tier is architecturally identical on every host — only the isolation boundary moves (VM on macOS, sandbox container on Linux). Rootless is the safe mode for agent workloads: damage ceiling is a user namespace, no host root, `/var/lib/docker` lives inside the disposable sandbox. Requires cgroup v2 delegation, user namespaces, rootless overlayfs (fuse-overlayfs fallback), and a dedicated e2e lane proving rootless *inside* a sandbox (the nested case). This is the riskiest ADD item; documented fallback if late: "on Linux hosts, point `DOCKER_HOST` at your system docker" (preserves CLI-contract portability while full parity finishes).
3. **The `vz docker` shim is deleted** via a deprecation window: facade GA ships, `vz docker` prints a deprecation notice pointing at the real `docker` CLI + facade, removal in the following release. Rationale: two backends for the same verbs is two truths; the shim's guardrails existed only because translation can't be verbatim.
4. **The agent surface is CLI + skill + `--json` — not MCP.** Same reasoning as the shim deletion: the MCP register maps 1:1 onto CLI verbs; an MCP server would be a second truth to keep conformant. MCP ships **post-1.0 as a thin adapter over the same gRPC client** (a wrapper like the CLI, never a second truth), triggered by: hosted sandboxes GA, user demand for tool-level permission gating, or an agent platform that cannot shell out. 1.0 obligations this imposes: universal `--json` on every verb, stable exit codes, machine-readable errors, and a refreshed skill covering the full verb set.

## KEEP — maintenance only

youki substrate (single-runtime rule; crun is the documented escape hatch) · `vz stack` deterministic reconciler · `vz build` (BuildKit-in-guest) · `fs_quick` checkpoints + macOS VM save/restore (Linux-native surface only) · `vz.json`/`vz run` UX · `vz-runtimed` as the single control plane · receipts/leases/events contract layer · macOS-guest flows (frozen beta, per call #1).

## CUT — removed or absorbed

- **`vz docker` shim** — subsumed by the facade; deprecated at facade GA, deleted the release after (call #3).
- **Full HTTP control-plane routing** (`vz-api` beyond docs/OpenAPI) — gRPC is the 1.0 machine surface; API-first platform ambition is post-1.0. Freeze `vz-api` to contract-docs + smoke-test status.
- **gvproxy revival** (`vz-662`) — NAT + MASQUERADE + socket proxy cover 1.0; deferred.
- **Nested-virt investment** (Virgil/Firecracker host path) — developer kernel profile keeps building; zero 1.0 investment.

## DEFER — named so they don't haunt the roadmap

MCP server (thin adapter; triggers in call #4) · `.vzcapsule` spec · federated mesh/scheduler/BYOC · hosted Linux target · warm VM pool (checkpoint restore covers the latency) · time-travel debugging · marketplace · multi-tenant auth/quota plane · **harness residency / worktree sessions / credential broker (the 2.0 track — see `docs/2.0-vision.md`)**.

## Exit gates — 1.0 ships when all five hold

1. Conformance matrix: no "no" cells in Tier-1/Tier-2 primitives, on both platforms.
2. Identical e2e suites green on macOS-VM and Linux-native: sandbox/stack/build lanes, plus the Docker lane (youki-only runtime proof, incl. nested rootless on Linux).
3. A real agent session (Claude Code *and* OpenCode) completes a build-test-commit loop entirely through `vz` verbs per the skill.
4. Every claim on `site/index.html` is either ACTIVE or the page is updated — the honesty gate.
5. Zero open P0/P1 beads.

## Top risks

1. **Rootless dockerd inside a sandbox (nested)** — works upstream but is the least-trodden path in the plan; own e2e lane, documented fallback (call #2).
2. **youki via containerd shim-v2** — credible but not upstream-proven at crun's level; gaps close in youki per the single-runtime rule; crun is the escape hatch (one config line + conformance re-run).
3. **Linux CI capacity** — "identical lanes on both platforms" needs Linux runners with KVM/nested-userns; verify early, not at the end.
